## 一、一句话结论

**下午花 90 分钟、8 个提交、试遍五种手段都没解决的浏览器跨域问题，晚上换成桌面形态后，用 20 行代码消失了。**

## 三、阶段 ④ 到底做了什么，为什么都白打

| 尝试 | 结论 |
|---|---|
| Cloudflare Worker 反向代理 | 方案成立，但依赖 `wrangler login`——**等了 42 分钟没等到，至今未登录** |
| vite dev server 当代理 | 只能自己用，给不了第二个人 |
| `server.cors=true` | Vite 6+ 默认只放行 localhost 来源，github.io 预检被拒 |
| 剥掉上游 CORS 头 | 真坑：上游自己也回 `ACAO:*`，与代理叠成 `*,*`，浏览器判非法 |
| `Access-Control-Allow-Private-Network` | Chrome PNA：公网 https 页 → localhost 预检必须带 |
| Key 走 query / body / 换头名 | 8 种参数名 × 3 种位置全试，`AuthenticationError` |
| 识别误填 VPN 端口的防呆 | 有价值（用户确实填错了），但**不解决问题** |

**这些不是白做**——网页版仍然需要它们。但它们全都在回答同一个问题：
「怎么让**浏览器**发出这个请求」。而正确的问题是：**「这个请求非得由浏览器发吗？」**

带教对象每天在自己的 mac 上用，答案显然是不。
Electron 主进程发请求根本没有同源策略，20 行 `webRequest` 头改写就完事：

```js
// 请求发出前摘掉 Origin（file:// 页面的 Origin 是字符串 "null"，方舟直接 403）
// 响应回来先删干净上游自己的 Access-Control-*，再换成放行值——否则叠成 "*,*" 照样被拒
```
实测：Electron 渲染进程直连 Coding Plan 端点 → **200，模型正常回话，零代理**。

> **判据留给下次**：当一个技术约束连续挡住 3 次以上、且每次绕过都引入新依赖（一个账号、一台服务器、一个别人要装的东西）时，
> 停下来问「换个形态这个约束还在不在」，而不是找第 4 种绕法。

## 四、桌面化阶段：做对的三件事

### 1. 选 Electron 不选 Tauri，是被「一小时预算」逼出来的正确决定

| | Tauri 2 | Electron 38 |
|---|---|---|
| 前置 | Rust 工具链 + 首编几百 crate | 只要 Node |
| SQLite | plugin-sql，原生编译 | **内置 Node 22 的 `node:sqlite`，零原生编译** |
| 包体 | ~10MB | 105MB |

包体大 10 倍是明确付出的代价。**约束（一小时）反而帮着砍掉了一个会让人纠结半天的选项。**

### 2. Dexie 兼容层：60+ 处调用，业务代码一行没改

存储层换引擎通常是最脏的活。做法是先数清楚现有代码**实际用到**了 Dexie 的哪些方法——
只有 `get/put/add/update/delete/bulk*/toArray/where().equals()/orderBy/filter` 这十来个。
照着实现一遍 `src/data/sqlite-table.ts`（约 60 行），`schema.ts` 按 `isDesktop()` 选后端，收工。

> **法则**：换底层前先量「调用面」有多大。多数时候你以为要重写全部，实际只要顶住一个很小的接口子集。

### 3. 业务判断全部留在渲染侧 TS，主进程只做存取

打分、任务生成、分类规则一行都不进主进程——那边没有 vitest。
这条纪律的回报在最后一小时兑现了：**补测直接抓出 3 个真 bug**。

## 五、四个 bug，没有一个是 review 看出来的

| # | bug | 后果 | 怎么发现的 |
|---|---|---|---|
| 1 | `fromTracking()` 缺空行守卫 | 导出 Excel 尾部空行 → 看板上一张**幽灵待办** | 补测 |
| 2 | `daily_water` 在 0 张卡时判不满足 | 没有日配件品类的厂子**永远收不了工**——一条提醒变成一道锁 | 补测 |
| 3 | `/停购\|下架/` 匹配上「在购-警示将下架」 | 一个还能买的物料被判死刑 | 补测 |
| 4 | 打包版签名失效 | **Apple Silicon 内核静默杀进程**：`open` 返回 0、无报错、无崩溃报告 | 用户点开 |

前三个来自同一件事：`generate.ts`（792 行）此前**零覆盖**。
「能跑」和「对」之间隔着的就是这些。

第 4 个是我的盲区：冒烟测试跑的是**未打包的 dist**，恰好绕过了唯一坏掉的那条路径——
`electron-builder` 配 `identity: null` 会完全跳过签名，包里留着原版 Electron 二进制的 linker 签名
（`codesign -dv` 显示 `Identifier=Electron`），换成我们的 `app.asar` 后签名失效。
**打包版从第一次构建就是坏的，而所有绿灯都没照到它。** 现已加 `afterPack` 钩子自动 ad-hoc 签名。

> **法则**：测试要覆盖**交付物本身**，不是覆盖交付物的近似物。
> 跑 dist ≠ 跑 .app，跑 dev server ≠ 跑线上产物。

## 六、并行开发的账

**打法**：三路调研并行 → 老架仲裁 → 定共享类型 → 五路工兵按文件边界并行 → 集成点只由老架碰。

这个结构本身是对的：`src/board/types.ts` 先定稿，逻辑侧和界面侧各写各的，合起来编译零冲突。
但执行层踩了四个坑：

| 坑 | 代价 | 下次怎么办 |
|---|---|---|
| API 529 把 4 个工兵一次性打掉，**零落盘** | ~12 分钟 | 重派预案常备；失败通知**必须自己 ls 盘核实**，不看报告 |
| 同一份活派了两次（原派没真死）撞车同写一批文件 | 一次返工判断 | 重派前先确认原 agent 真的死了 |
| 子代理报告「已完成」后**仍在写盘**，中途读到的是它的调试草稿（38 行 console.log） | 差点把草稿当交付物 | 验收以「全量回归」为准，不看单次快照 |
| 只读调研 agent 集体误报「仓库被别人改了」 | 三份报告都要澄清 | 派只读任务时提前说明「会看到别人的改动」 |

**最该记住的一条**：子代理的自述报告不能当验收依据。三次都是自己跑 `tsc + vitest + guard` 才拿到真相。

## 七、我自己犯的两次同一个错

`ELECTRON_RUN_AS_NODE=1` 从早先的探测命令泄漏进后续 shell，
导致 Electron 被当纯 node 跑（`require("electron")` 返回路径字符串）。
**同一个坑踩了两次**，第二次时我已经诊断过一次了，还是又花了三轮才想起来。

> 教训不在「知道这个坑」，在**「探测性命令改了环境，用完要立刻收回」**。

另外，一小时的目标**没做到，实际约 100 分钟**——主因是 529 重派（~12 分钟）加桌面壳三个启动坑。

## 十、三条带得走的法则

1. **约束挡住 3 次就换形态，别找第 4 种绕法。** 每一种绕法都在给交付物加一个别人要装的东西。
2. **测试要覆盖交付物本身。** 跑 dist ≠ 跑 .app。所有绿灯都可能照不到唯一坏掉的那条路径。
3. **换底层前先量调用面。** 多数「大重构」实际只需要顶住一个很小的接口子集。
