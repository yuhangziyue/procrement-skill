## 1. 采购单据流全景（U8 标准流程，多源一致·通行）

```
[生产/计划]      [采购]           [采购/仓库]      [仓库]           [财务]
 生产表/缺料 →  请购单(可选) →  采购订单 PO  →  到货单  →  采购入库单  →  采购发票 → 采购结算 → 付款
                 ↑审批用          ↑核心单据       ↑货到门口      ↑真正增加库存     ↑三单匹配
```

**每张单据是什么、谁做**：

| 单据 | 作用 | 通常谁做 | 关键点 |
|---|---|---|---|
| 请购单 | 内部申请「要买什么」 | 需求部门或采购 | 审批载体；有的公司不用 |
| **采购订单** | 对供应商的正式订购 | **采购员** | 核心单据。审核后才生效、才能被下游参照 |
| 到货单 | 记录货到了、实到多少 | 采购或仓库 | 参照采购订单生成；质检从这里触发 |
| **采购入库单** | 货物正式进入库存 | **仓库** | 参照到货单（或订单）生成；审核后库存数量才增加 |
| 采购发票 | 供应商开票录入 | 采购或财务 | 与订单、入库单三单匹配 |
| 采购结算 | 入库单与发票勾稽 | 财务 | 之后走应付付款 |

## 2. 必须刻进肌肉记忆的四个系统概念

1. **参照生成**：下游单据不要手工敲，一律「参照」上游单据生成（到货单参照订单、入库单参照到货单）。
   参照会自动带出供应商、物料、价格，并回写上游的「累计到货/累计入库」——**手工敲单 = 数据链断裂 = 跟踪报表全是空的**。
2. **审核才生效**：单据保存 ≠ 生效。订单不审核，下游参照不到；入库单不审核，库存不增加。
   反向：已被下游参照/已审核的单据要改，必须先弃审（或走变更），而且下游已生成单据时上游改不动——**下单前把字段核对好，比事后改省十倍力气**。
3. **单据状态**：开立（保存未审）→ 审核（生效）→ 关闭（不再执行，剩余量不再期待到货）。手工关闭订单行用于「这行不要了」。
4. **暂估入库**：货到票未到，月底系统按订单价暂估入账，票到后自动/手工冲回。采购只需知道：**入库和发票可以不同月，不影响你收货**，但月底财务催票时要配合追发票。

## 3. 常用操作入口（U8+ 典型菜单路径 ⚠️ 待实机核对）

| 要干什么 | 菜单路径 |
|---|---|
| 开采购订单 | 供应链 → 采购管理 → 采购订单 → 采购订单（增加） |
| 开到货单 | 供应链 → 采购管理 → 到货单 → 增加 → 参照「订单」 |
| 开采购入库单 | 供应链 → 库存管理 → 入库业务 → 采购入库单 → 参照「到货单」 |
| 查现存量 | 供应链 → 库存管理 → 库存账 → 现存量查询 |
| 查订单执行 | 供应链 → 采购管理 → 报表 → 采购订单执行情况统计表（名称待核对） |
| 查供应商历史价 | 采购管理 → 价格资料 / 供应商存货价格表 |

## 4. 基础档案常识

下单时选的供应商、存货都来自**基础档案**（基础设置 → 基础档案）。采购员通常没有建档权限，但要会看：

- **供应商档案**：编码、名称、税率、币种、付款条件——订单上的税率/账期从这里带出
- **存货档案**：存货编码是全公司唯一语言，**下单认编码不认名称**（同名不同规格的料太多）
- 新供应商/新物料没档案 → 先找管理员建档，再下单，**不要借用相近编码顶替**——库存账会乱到没法收拾

## 5. 版本差异速记（万一不是 U8+）

- **T+/好业财**：菜单叫「业务 → 采购管理」，单据更简化，常无到货单环节
- **U9 cloud**：叫「采购收货单」而非到货单，流程概念一致
- **YonSuite**：云端，入口在浏览器，流程同样是 订单→到货→入库 三段式

**概念是通的：核心永远是「订单生效 → 货到登记 → 入库增加库存 → 回写订单累计数」**，换版本只是找菜单。
