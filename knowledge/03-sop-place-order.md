# 03 · 操作1：下单 SOP

> 前置：读过 [02-u8-basics.md](02-u8-basics.md)，版本确认清单已回填。
> 覆盖两个场景：**场景1 生产表缺料下单**、**场景2 加单**。

## 场景1：生产部门给生产表，缺的料去找供应商下单

### 第一步：把「生产表」翻译成「缺料清单」（下单前的算账，最重要的一步）

1. 拿到生产表，逐行确认每个物料的**存货编码**（对不上编码的先和生产核对，不猜）
2. 查库存：`供应链 → 库存管理 → 现存量查询`，记下每个料的**可用量**（注意看「可用量」而不是「现存量」——已被其他订单预占的不能算）
3. 查在途：`采购订单执行情况统计表`（或订单列表），看该料**已下单未到货的量**
4. 算缺口：**下单量 = 生产需求 − 可用库存 − 在途量**（结果 ≤ 0 就不用下）
5. **多仓时先算调拨（调拨优先于采购）**：本仓有缺口 → 查他仓现存量，
   **他仓可调量 = 他仓现存 + 他仓在途 − 他仓自己生产表的需求 − 他仓安全量**。
   两张生产表都拿到才能算这一步；可调量 > 0 先开调拨单覆盖，**剩余缺口才下采购单**；
   调拨的运输时间同样要满足需求日期，来不及的部分照常采购
6. 产出一张缺料清单：编码 / 名称规格 / 缺口数量（已扣除调拨覆盖）/ 需求日期 / 调拨明细单列

> 🔴 新手最常见事故就是跳过 2、3 直接照生产表下单 → 重复采购、库存积压。**每次都算，一次都不跳。**

### 第二步：定供应商与价格

1. 老物料：查 `价格资料 / 供应商存货价格表` 和历史订单，用**现有供应商 + 最近成交价**
2. 价格有变动或新物料：找 2~3 家询价（见 [01-skill-tree.md](01-skill-tree.md) §2.1），确定后请管理员维护价格档案
3. 交期倒推核对：供应商交期能不能赶上生产需求日期？赶不上→提前跟生产沟通（调计划或拆分批到货），**不要下一张注定迟到的单然后祈祷**

### 第三步：在 U8 开采购订单

1. 若公司要求走请购：先录请购单送审批，批完后在采购订单界面**参照请购单**生成
2. 直接下单：`供应链 → 采购管理 → 采购订单 → 增加`
   - 表头：供应商（编码选）、订单日期、币种税率（档案自动带出，核对一遍）
   - 表体：逐行录 存货编码 / 数量 / 无税或含税单价 / **计划到货日期**（这个字段是后面入库和跟踪的锚点，必填且填真实承诺日期，不填生产需求日期）
   - 同一批缺料涉及多个供应商 → **按供应商拆成多张订单**（一张订单一个供应商）
3. 保存 → 自查一遍（编码、数量、单价、税、到货日期）→ 审核（或提交审批）
4. 打印/导出订单发给供应商，**要求书面回签确认交期**——回签前订单只是你的一厢情愿

### 第四步：收尾登记

- 把订单号、供应商、承诺交期登进跟单表（见 [05-sop-tracking.md](05-sop-tracking.md)）
- 回复生产部门：哪些料已下单、预计何时到、哪些有交期风险

## 场景2：加单

加单 = 在原有生产计划外临时追加的采购需求。和场景1 的区别在**确认环节更重，动作更快**。

### 第一步：确认三件事再动手

1. **谁批的**：加单必须有明确来源（生产主管/计划的书面通知，微信截图也算留痕），口头喊一嗓子不算
2. **要多少、何时要**：数量和需求日期落到文字
3. **还是先算账**：加单一样要过「可用库存 − 在途」这道算术，急单尤其容易重复下

### 第二步：定供应商

- **优先原供应商、原价格加单**——最快，且价格有据可依
- 原供应商交期赶不上 → 启用备选供应商，或和原供应商谈加急（可能加价，加价要请示授权）
- 加急运费谁出、是否加价，**下单前谈清并写进订单备注**

### 第三步：开单

- **新开一张采购订单**，不要去改已审核的原订单（原单可能已有到货记录，改动会搅乱数据链）
- 订单备注写明：「加单，对应原订单号 XXX / 需求来源：X月X日 XX 通知」
- 其余步骤同场景1 第三、四步；急单要**当天完成审核和供应商回签**，并在跟单表上标「急」

## 下单自查清单（每张订单发出前过一遍）

- [ ] 算过 可用库存 + 在途，数量是净缺口
- [ ] 存货编码与生产表核对过，不是靠名称猜的
- [ ] 单价与价格档案/报价单一致，含税口径明确
- [ ] 计划到货日期 = 供应商真实承诺，不是需求日期
- [ ] 一单一供应商；加单标注了来源和原单号
- [ ] 已审核 + 已发供应商 + 已要求回签
- [ ] 已登跟单表、已回复需求部门
